## Project Overview: HelpLocal MVP
HelpLocal is a mobile application that safely connects **vulnerable citizens (Requestors)** with **vetted neighborhood volunteers** for daily chores and errand support. 

To ensure safety and trust, this project focuses entirely on the core **User Registration, SMS OTP Verification, and Automated Identity Check** system.

## Repository Structure & Project Steps
This repository contains the complete, step-by-step project delivery lifecycle across 15 standard Business Analysis artifacts. All files are located inside the **Documentation** folder:

### Phase 1: Planning & Strategy
* **01. Business Case:** Explains why the app is needed, project costs, and financial benefits.
* **02. Stakeholder Register:** Lists everyone involved in the project, from company executives to compliance teams.
* **03. Elicitation Plan:** Details how requirements were gathered using workshops and user feedback.

### Phase 2: System Requirements
* **04. Requirements Traceability Matrix (RTM):** Links business goals directly to technical features and testing states to prevent missing scope.
* **05. Business Requirements Document (BRD):** Defines exactly what features are included in the launch and what features are saved for later.
* **06. Use Case Document:** Step-by-step descriptions of how users interact with screens, including error loops.

### Phase 3: Visual Flow Diagrams
* **07. Process Flow (BPMN):** A swimlane visual chart mapping how code moves across the mobile app, backend server, and third-party systems.
* **08. Data Flow Diagram (DFD):** Tracks exactly how data pieces (like phone numbers and image uploads) travel between the server and databases.

### Phase 4: Agile Development & Code Data
* **09. Data Dictionary:** Outlines precise database rules, data formats, and text limits for our engineering team.
* **10. User Stories:** Backlog items written in agile formatting (`As a... I want to... So that...`) with clean acceptance checklists.

### Phase 5: UI Mockups, Testing & Release
* **11. Wireframes & Mockups:** Plain-text visual layouts showing exactly where fields and buttons sit on the mobile screens.
* **12. Non-Functional Requirements (NFR):** Establishes hard technical benchmarks for app speed (<200ms latency), uptime (99.9%), and AES data safety encryption rules.
* **13. QA Test Cases:** Explicit validation scripts testing positive, negative, and edge-case behaviors for software testing.
* **14. UAT Sign-Off Charter:** The official business delivery sign-off documenting stakeholders' final approvals.
* **15. Change Request Analysis:** A mock assessment calculating schedule impacts if a stakeholder requests an unexpected mid-sprint feature change.
